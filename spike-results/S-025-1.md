# S-025-1 — cross-window jitter, OS animations, caret and IME (pending)

## Question

Spike register S-025-1 (ADR-025 D1, D3; ADR-024 D3): when UI main hands a mode change from one frameless window to
another with a shared `t0`, do the two windows move and animate at most one frame apart on Windows (DWM), macOS and
X11; can each platform's OS show/hide animation be disabled per window; are the caret and selection restored in the
other renderer; and how does each platform end an in-progress IME composition at the switch?

## Setup

- `spikes/S-025-1/modeWindows.e2e.ts` (L9, the ISSUE-312 harness over `pnpm build`): two frameless stand-in windows,
  one transition run from `t0` = UI main clock + 16 ms; the first renderer frame of each after `t0`, the time each
  window reports its final bounds after one `setBounds` each in the same main-process tick, and the draft with a
  backward selection flushed from one renderer and restored in the other. Its test:
  `[S-025-1, ADR-025] two mode windows moved in one run differ by at most one frame and the caret and selection are restored after the hand-off`.
  It runs in the E2E release lane on Windows, macOS and Linux (Xvfb), since `playwright.config.ts` matches
  `spikes/**/*.e2e.ts`. `S0251_REPORT=<file>` writes the measures as JSON.
- `spikes/S-025-1/manual.md`: how to run the case per OS, the load-bearing break (`OS_WINDOW_ANIMATION = true`), and
  the manual checks the case cannot see (OS show/hide animation from a 60 fps screen recording; IME composition at the
  switch).

## Status

Not run yet on any OS. The case was not run on the issue's Windows development machine, because it shows the app's own

exists, and the load-bearing break has not been shown.
