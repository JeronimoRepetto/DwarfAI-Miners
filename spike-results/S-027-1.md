# S-027-1 — the Scoop zip, Scoop's hooks on update and uninstall, and the portable target

## Question

Spike register S-027-1 (ADR-027 D1; ADR-016 item 7; OQ-59): electron-builder 26.15.3's `portable` extraction and the
`zip` target layout for Scoop; whether `pre_uninstall` runs on `scoop update`, and how the hook tells an update from an
uninstall.

What it gates: the Scoop artifact (zip, OQ-33 A), built by ISSUE-275, which has no fallback: if the hook cannot tell
an update from an uninstall, ISSUE-275 stops and reports. Owner role: build engineer.

## Setup

Ran on a GitHub-hosted `windows-latest` runner, packaging spike lane `.github/workflows/spikes-package.yml`, run
39130693732 (2026-10-18, `main` at `a222591f`). No person ran anything. The leg packaged 0.13.1 (`release/`), the same
commit at 0.13.2 (`release-next/`) and electron-builder's `portable` exe (`release-portable/`). The Scoop and portable
parts ran as the standard user `dwarfai-ci` that `scripts/ci/run-unelevated.mjs` creates. Scoop came from its official
installer (`get.scoop.sh`); the zips were served from `127.0.0.1` through a local manifest whose four hooks each log
`$cmd`, `$app`, `$version`, `$global`, `$dir` and the command line (`scripts/ci/packagingSpikes.mjs` `scoopManifest`).

A second run, 39134423991 (2026-10-18, `spike/issue-328-records` at `89dd3f09`, same image, Scoop 0.6.0), repeated
the three parts with the fixed harness: the entry list read with the system bsdtar, the product logs saved before the

## Decision

- **Zip layout (ISSUE-275).** The release zip holds the app at its root (`DwarfAI-Miners.exe` and `resources/` side by
  side, no top folder), and Scoop installs it as it is: the manifest needs no `extract_dir`. Measured through Scoop's
  own extraction and, in run 39134423991, the entry list.
- **Portable (OQ-33 B).** The portable exe does not run in place: it extracts itself to `%TEMP%` and runs from there,
  and the Host runs from its versioned copy as on every other layout. OQ-33 B is **not** restored; the Scoop artifact
  stays the zip (OQ-33 A).
- **Hooks (OQ-59), for ISSUE-275.** **`scoop update` runs `pre_uninstall`**, and the hook tells it from an uninstall
  by `$cmd`: `update` on an update, `uninstall` on an uninstall (run 39134423991). A `pre_uninstall` that runs
  `--revert-integrations` only when `$cmd` is `uninstall` meets the register's rule. Run 39205769685 measured the same
  with a Host running from its copy: `scoop update` called every hook with `$cmd = update` and the Host survived, and
  `scoop uninstall` called them with `$cmd = uninstall`. Scoop never stops the Host, so the uninstall-time
  `--revert-integrations` is the only step that ends it.
- **A finding ISSUE-275 must handle.** With the UI (the tray) still running from the Scoop folder, `scoop uninstall`
  ran `pre_uninstall` and only then refused, exiting 0 with the app still installed. A `pre_uninstall` that runs
  `--revert-integrations` would therefore revert integrations and stop the Host on an uninstall that Scoop then
  abandons. Proposal for the lead (unverified): the hook checks for a DwarfAI process still running from `$dir` and
  does nothing in that case, leaving the revert to the uninstall that succeeds. Run 39134423991 repeated the refusal,
  and with the UI ended both commands ran every hook and finished. `scoop update` with the tray running also does
  nothing, so the update notes ask the person to quit DwarfAI first.
- **The Host did not start from the Scoop install in runs 1 and 2: a launcher defect, now fixed.** Scoop starts the app
  through the `current` junction; the versioned copy (`src/ui-main/hostLauncher/versionedCopy.ts`, `fs.cp` of the
  source root without dereferencing it) copied the junction, not the tree, and the manifest check refused it
  (`MANIFEST_MISMATCH`). #1440 (GitHub #1439) copies from the real path, and #1446 (GitHub #1445) runs the Host entry
  from the copy when the install is a link. Run 39205769685, on `main` with both, started the Host from the Scoop
  layout, and the Host survived `scoop update` and `scoop uninstall`.
- **Verdict passed (run 39205769685).** Each part of the exit criterion is measured on a packaged build under Scoop:
  the zip layout works as installed (no `extract_dir`); the portable extraction is recorded (not in place, so OQ-33 B
  is not restored); and with a Host running from its copy, `scoop update` calls `pre_uninstall` with `$cmd = update`
  while `scoop uninstall` calls it with `$cmd = uninstall`. A `pre_uninstall` that runs `--revert-integrations` only
  when `$cmd` is `uninstall` therefore never runs it on an update and runs it on every uninstall Scoop carries out.
  The hook itself, with that rule and the "UI still running" guard above, is ISSUE-275's to build and test, and its
  lane run re-checks it on the real hook. Nothing in this record is left for the owner.
