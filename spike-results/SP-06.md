# SP-06 — live-stream and transcript ids per provider

## Question

Spike register SP-06 (ADR-006, ADR-007): per driver, are the `unitKey` and the message ids identical between the live
stream and the provider's transcript? Claude: the `stream-json` assistant `message.id` and `uuid` against the session
JSONL's. Codex: the app-server item and turn ids against the rollout lines. OpenCode: the server's event stream
against its session store. If they are identical for a provider version, ADR-006's once-only rule can credit usage
from either path; if not, one path stays authoritative per session.

## Setup

The evidence is a real-CLI recording with the maintainer's own login (`17` §4, §5.5), which no agent and no CI job can
make. This issue built the tools the maintainer runs:

- `spikes/SP-06/captureTranscript.mjs`: copies a provider file of a throwaway session (the transcript, and the live
  stream as the case's `stream` file) into `fixtures/<provider>/observer/<version>/<case>.raw.*`. It refuses outside
  the real-CLI lane (`CI` set, `RUN_INTEGRATION` not `1`, provider not in `DWARFAI_REAL_CLI`) and reads no provider
  config or credential (ADR-008 item 2). Then `scripts/fixtures/scrub.mjs` writes the fixture set.
- `spikes/SP-06/idCorrespondence.mjs`: for one case, the key paths under which both files hold the same id
  (`message.id` ↔ `message.id`, `session_id` ↔ `sessionId`, …), and for Claude the ADR-006 units (`message.id`, usage
  of the last row that carries one): how many are shared and on how many the usage agrees. Counts only.
- `spikes/SP-06/observer-cases.md`: the cases and their exact prompts (`one-turn`, `tool-continuation`).
- `spikes/SP-06/observerCapture.os.test.mjs` (OS lane, synthetic input): the capture's refusals and its output, the
  scrubber's round trip over it, and that the correspondence is the same before and after scrubbing (the scrubber maps
  each id to the same fake id across one case).

## Results

None yet. No provider version has been recorded, so no correspondence is known.

- **Claude:** recordable by the maintainer with `claude -p … --output-format stream-json --verbose` (the live stream
  is stdout) and the session's JSONL (the transcript).
- **Codex:** the register asks for the `codex app-server` item ids, and the app-server is a JSON-RPC server that needs
  a client. The Codex driver issue's recording adapter (`scripts/fixtures/record.mjs`, `RECORDING_ADAPTERS`) is that
  client, and it does not exist yet. The guide records `codex exec --json` beside the rollout as a lead only. That is a
  different protocol and cannot pass the spike for the app-server.
- **OpenCode:** the server's event stream (`/event`, captured with `--sse`) against the session store. The store side
  needs a read of OpenCode's SQLite store as SQL text, which is not built here. The guide records the event stream,
  and `opencode export` where the installed CLI offers it.

## Decision

- **Exactly one authoritative usage path per session stays in force for every provider (ADR-006 item 5):** the
  driver path for a session DwarfAI launched, the transcript path for an observed one, kept for the session's whole
  life; the other path's usage is recorded for diagnostics and never credited. ISSUE-076 builds `dwarfs.usage_path`
  with that rule and offers nothing that relies on a correspondence. ISSUE-123 lists it in `parity-cut-1.md`.
- **Passed for a provider version** means: for every recorded case of that version, `idCorrespondence.mjs` reports
  `units.onlyStream` = 0, `units.onlyTranscript` = 0 and `units.usageDiffers` = 0 (Claude), or, for the other
  providers, one id path shared by every unit on both sides; and the scrubbed fixtures are committed under
  `fixtures/<provider>/observer/<version>/`, where they feed the ADR-006 once-only contract for that provider.
  Passing removes nothing by itself: changing the one-path rule is ISSUE-076's decision, taken with this record.

Verdict **partial**. The recording and comparison tools exist and pass on synthetic input. No provider version has
been recorded, and no fixture is committed, so TC-319-02 is not met yet.
