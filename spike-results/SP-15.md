# SP-15 — provider session id on resume

## Question

Spike register SP-15, alias S-030-2 (ADR-015 item 7; ADR-030 D5): per CLI and version, does a resumed session keep its
provider session id? This covers Claude `--resume` and `--fork-session` on stream-json, `claude-agent-acp`
`session/load`, Codex `thread/resume` and ACP `session/load`. Does an idle resumed process use quota?

What it gates: dwarf identity across resume (the UNIQUE provider key) and silent resume after a Host crash (ISSUE-173),
and the `resume` value of the Claude stream-json driver. Owner role: provider devs / driver engineer. Issue:
ISSUE-321 (Claude stream-json part).

## Setup

Real-CLI lane (`17` §4, §5.5). **Run by an agent on the maintainer's Windows 11 machine on 2026-10-16, under a one-off
owner exception to AGENTS.md §0.3, with the owner's own Claude login and no human at the screen.** Same scratch tool and
environment as `SP-08.md` (Setup). Three Claude processes ran one after another in one throwaway repository.

## Commands

```powershell
node $K\sp3a.mjs run sp15-resume
```

argv of the three steps (from the summary; the shared flags are `--permission-mode default --permission-prompt-tool
mcp__dwarfai__permission --mcp-config <mcp-config> --strict-mcp-config --disallowedTools AskUserQuestion`):

```text
1 launch  claude -p --input-format stream-json --output-format stream-json --verbose --session-id <session-id> <shared>
2 resume  claude -p --input-format stream-json --output-format stream-json --verbose --resume <session-id> <shared>
3 fork    claude -p --input-format stream-json --output-format stream-json --verbose --resume <session-id> --fork-session <shared>
```

Step 2 kept stdin open for 120 s after its result. Then `node scripts/fixtures/scrub.mjs sp15-resume.raw.*` (exit 0)
and the runbook's privacy check (no match).

## Results

Windows 11 Pro 10.0.26200.9457, x64, Claude Code 2.1.301. macOS and Linux: **not run**.

| Step     | `system/init` | Session id equals the launched one            | Reply   | Exit |
| -------- | ------------- | --------------------------------------------- | ------- | ---- |
| 1 launch | 5207 ms       | true                                          | `one`   | 0    |
| 2 resume | 4564 ms       | **true** (in `system/init` and in the result) | `two`   | 0    |
| 3 fork   | 4554 ms       | **false** (a new id)                          | `three` | 0    |

- Idle resumed process (step 2, 120 s with stdin open after its result): **0** lines printed.
- Quota use of the idle process: **not measured**. The tool cannot see usage outside the stream, and the stream was
  silent.

## Decision

- **Claude Code 2.1.301, stream-json: `--resume <id>` keeps the provider session id; `--resume <id> --fork-session`
  gives a new id.** The driver's `resume` value (ISSUE-150) and the silent resume after a Host crash (ISSUE-173) may rely
  on the kept id for this version, and a fork must be handled as a new provider identity.
- **Verdict partial**: the quota use of an idle resumed process is not recorded, the other CLIs of the register
  (`claude-agent-acp`, Codex, ACP) have not run, and only Windows ran. macOS and Linux are not run and are not claimed.
