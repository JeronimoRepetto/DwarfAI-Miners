# S-027-3 — the per-user installer and uninstaller against a running Host

## Question

Spike register S-027-3 (ADR-027 D1; ADR-016 item 7; ADR-002; OQ-59): the `nsis` installer's running-app check and its
uninstaller against a Host running from the versioned copy, and the upgrade flag (`isUpdated` / `--updated`,
UNVERIFIED) the old uninstaller receives during an upgrade.

What it gates: the downloadable installer channel, built by ISSUE-276, which has no fallback: if the installer kills
or blocks on the Host, ISSUE-276 stops and reports. Owner role: build engineer.

## Setup

Ran on a GitHub-hosted `windows-latest` runner, packaging spike lane `.github/workflows/spikes-package.yml`, run
39130693732 (2026-10-18, `main` at `a222591f`), as the standard user `dwarfai-ci` that
`scripts/ci/run-unelevated.mjs` creates (the Host refuses to start elevated, ADR-002 D6). No person ran anything. The
harness `spikes/S-027-3/installerVsHost.mjs` installs the 0.13.1 setup silently, starts the installed app, upgrades to
0.13.2 with the Host running, starts the upgraded app and uninstalls, watching every process each step starts.

## Decision

- **For ISSUE-276:** the per-user installer installs silently without elevation to `%LOCALAPPDATA%\Programs\dwarfai-miners`
  and writes no `InstallLocation`; anything that needs the install folder reads it from the uninstall string's
  folder. Its running-app check looks only at processes whose path is under the install folder, so a Host running
  from `%LOCALAPPDATA%\DwarfAI\host\<version>` is outside what it checks (read from the command line it ran, not yet
  measured against a running Host).
- **Not measured yet:** whether an upgrade kills or blocks on the running Host, the flag the old uninstaller receives,
  whether `--revert-integrations` runs on an upgrade and on a removal, and what an uninstall leaves. The harness now ends
  the installed UI before the upgrade and before the uninstall (the register asks about the Host, which runs from its
  copy), and saves the product logs.
- **ISSUE-276's gate stays closed**: it builds and tests its hooks, and merges only after a lane run records the
  upgrade and removal with a running Host. **Verdict partial.** Whatever is still open when v1 is cut is listed as an
  R-16 known limit by the v1 checklist (later: ISSUE-281); for the installer there is no fallback, so an open upgrade
  question blocks the installer channel rather than shipping a guess.
