# SP-07 — Kimi and Kiro against their installed versions

## Question

Spike register SP-07 (ADR-009 D4, D6; ADR-011): launch, permission (interactive, or `policy-only` with a verified
non-interactive deny), questions and resume for Kimi and Kiro against their installed versions, with recorded fixtures.

What it gates: Kimi and Kiro in the public v1 catalog (OQ-22) and decision O-11; ISSUE-158 (their drivers). Owner role:
provider devs. Issue: ISSUE-326.

## Setup

Real-CLI lane (`17` §4, §5.5), same machine, exception and isolation as `SP-12.md` (Setup), with the owner's own Kimi
login (`kimi provider list`: `managed:kimi-code type=kimi source=oauth`). No auto-approve mode: the ACP mode stayed at
`default`, never `yolo` or `auto`.

- **Kimi Code 0.41.0, through `kimi acp`.** The package's K1 driver is `@moonshot-ai/kimi-agent-sdk`, which was not
  installed or run; ACP is the closest available stand-in.
- **Kiro**: `kiro-cli` is not installed on this machine, so nothing ran.

## Decision

- **Failed for this run.** Neither provider has launch, permission, questions and resume fixtures, so **neither Kimi nor
  Kiro enters the catalog**, and **ISSUE-158 closes as not needed, with this record linked** (OQ-22; `21` §8).
- The catalog stays open (ADR-009 D4): either provider can join later with no contract change, after a rerun with a
  Kimi plan that has model access (and through the K1 SDK driver, or ACP if the package changes the driver), and with
  `kiro-cli` installed.
- The Kimi agent SDK row of S-008-1 is updated in `S-008-1.md` (ISSUE-326 addendum); it bundles nothing while the Kimi
  driver is not built.
