# S-011-1 — the meaning of `on-verified` for the OpenCode plugin

## Question

Spike register S-011-1 (ADR-011 items 2, 7; ADR-016 item 5): is a plugin file written just before a launch loaded by
the next Host-launched `opencode serve`, and by a person-run server without a restart? Does OpenCode signal that the
plugin is loaded? Is OpenCode's launch-time deny setting honoured?

What it gates: the meaning of `on-verified` ("written and read back" until then) for the toggle (ISSUE-228), the plugin
ask channel (ISSUE-229) and the 4a switch (ISSUE-235); the OpenCode row of ADR-011 item 2. Owner role: provider dev
(OpenCode). Issue: ISSUE-327.

## Setup

Real-CLI lane (`17` §4, §5.5), same machine, exception and isolation as `SP-12.md` (Setup), with the owner's own
OpenCode setup. The probe plugin is a zero-import `.opencode/plugin/sp-probe.js` that appends a marker line (with the
process id) when it is initialised.

Server kinds:

- **Host-launched**: an `opencode serve` started after the plugin file was written.
- **Person-run**: an `opencode serve` that was already running when the plugin file was written.

## Commands

```text
opencode serve --port <port> --print-logs
GET  /config?directory=<repo>                        # lists the file under plugin
GET  /event                                          # plugin.added events
POST /session ... prompt_async                       # first directory-scoped request
POST /instance/dispose                               # person-run kind only
OPENCODE_CONFIG_CONTENT={"permission":{"edit":"deny","bash":"deny","webfetch":"deny"}}   # deny case
```

## Results

Windows 11 Pro 10.0.26200, x64, OpenCode 1.18.32. macOS and Linux: **not run**.

| Version / server kind  | Plugin load                                                                                                                                                                                                  | Loaded signal                                                                                                                                                                                | Deny                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.18.32, Host-launched | loaded at the first directory-scoped request; the marker's process id is the server's                                                                                                                        | **none**: `GET /config` lists the file under `plugin` (discovery, not proof of loading); the `plugin.added` events name only built-in ids; the `--print-logs` INFO lines have no plugin line | honoured: `/config.permission` shows the setting; asked to write a file, the agent had no write, edit or bash tool, the file was not created, and no `permission.*` event came (one turn) |
| 1.18.32, person-run    | **not loaded** by the next session in a directory the server had already opened, without a restart, nor after `POST /instance/dispose`; **loaded** for a directory opened for the first time after the write | none (as above; no `plugin.added` for it)                                                                                                                                                    | not run for this kind                                                                                                                                                                     |

Side effects of the deny turn: the session ran with the owner's global OpenCode setup, whose global plugins include the
old app's permission plugin and whose MCP servers include a memory server. The agent called that server and wrote one
memory row to the owner's store. The sessions of every probe stay in the owner's OpenCode history.

## Decision

- **`on-verified` means "written and read back"** for ISSUE-228 and ISSUE-229 (ADR-011 item 2): no loaded signal was
  identified in OpenCode 1.18.32.
- **For a person-run server, written-and-read-back does not imply loaded** for a directory that server already opened:
  it needs a server restart. The toggle and the ask channel must not claim that the plugin is active there; ADR-011
  item 7's card rule while `on-verified` applies.
- **The launch-time deny setting is verified for a Host-launched server** (`OPENCODE_CONFIG_CONTENT` permission deny).
  It was not run for a person-run server.
- **Verdict partial**: the deny case of the person-run kind is not run, and only Windows ran. macOS and Linux are not
  run and are not claimed.
