# S-019-2 — which Electron fuses electron-builder 26.15 sets per target

## Question

Spike register S-019-2 (ADR-019 item 5): which fuses `electron-builder` 26.15 can flip per build target, and asar
integrity on the Linux AppImage. ADR-019 item 5 asks for `EnableNodeOptionsEnvironmentVariable=false`,
`EnableNodeCliInspectArguments=false`, `EnableCookieEncryption=true`, `OnlyLoadAppFromAsar=true`,
`EnableEmbeddedAsarIntegrityValidation=true` (where supported per OS), with `RunAsNode` kept on because the Host runs
the app executable with `ELECTRON_RUN_AS_NODE` (ADR-002 D1).

What it gates: ISSUE-269 (flip the fuses at package time) and the v1 checklist (ISSUE-281). Owner role: build
engineer.

## Setup

Three runs of the packaging spike lane `.github/workflows/spikes-package.yml` on GitHub-hosted runners, one leg per OS
(`windows-latest`, `macos-15` unsigned with `-c.mac.identity=null`, `ubuntu-latest`), same runner images in both:

1. Run 39130693732 (2026-10-18, `workflow_dispatch` on `main` at `a222591f`).
2. Run 39134423991 (2026-10-18, `workflow_dispatch` on `spike/issue-328-records` at `89dd3f09`, which carries the lane
   fixes of run 1 and a new step that starts the fused build).
3. Run 39205769685 (2026-10-19, `workflow_dispatch` on `main` at `819dd03d`), after the corrected fused hook
   (`spikes/S-019-2/afterPack.fused.mjs`, merged in `08b048bf`): the same reads, and the fused-build start on every OS.

No person ran anything; the record was written by an agent from the uploaded evidence.

Each leg packaged the release targets twice from the same commit: once as `ci.yml`'s `package` job does (`release/`),
and once with the ADR-019 item 5 set (`spikes/S-019-2/electron-builder.fused.cjs`, into `release-fused/`; in both runs
the set was asked of electron-builder through its `electronFuses` option). `spikes/_packaged/extract.mjs` extracted
every artifact with the OS's own tools, and `spikes/S-019-2/fuses.packaged.mjs` read the fuse wire of the executable
(or of `Electron Framework` on macOS) and the asar integrity record of every unpacked app and every extracted
artifact. In run 2, `spikes/SP-03/packagedCopy.mjs` then started one fused artifact per OS (Windows zip, macOS arm64
zip, Linux AppImage; as the standard user of `scripts/ci/run-unelevated.mjs` on Windows) and recorded whether its Host
came up from the versioned copy.

- **electron-builder 26.15.3 sets the whole ADR-019 set on every target** of the three OSes: every fused artifact

- **Asar integrity on Linux.** No Linux artifact carries an integrity record, with or without the fuse set, while

### Does the fused build start its Host? (run 2)

The question behind this step: `RunAsNode` stays on, but `OnlyLoadAppFromAsar` and asar integrity change what the
executable will load, and the Host runs the app's own executable under `ELECTRON_RUN_AS_NODE=1` with
`resources/app.asar/out/host/main.js` (ADR-002 D1). If the set made that start impossible, ADR-019 item 5 and ADR-002
D1 would conflict.

| OS      | Fused artifact started | Result                                                                                                                                                                                                                                                                |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows | the zip                | **Host started.** Copy of 102 files in 3.8 s, Host identity at 6.3 s, running `host\0.13.1\DwarfAI-Miners.exe …\resources\app.asar\out\host\main.js`; it outlived the UI; second start reused the copy, Host at 2.0 s; boot log complete (`windows-start-host.jsonl`) |
| macOS   | the arm64 zip          | **not reached: build-order defect of the spike's configuration** (below). The UI started and logged `versioned-copy` failed, `errCode: MANIFEST_MISMATCH`, then `host.spawn` failed with the same code; no Host process was ever spawned                              |
| Linux   | the AppImage           | **not reached: the same defect.** The UI logged the same `MANIFEST_MISMATCH` sequence                                                                                                                                                                                 |

- **The conflict hypothesis is refuted.** The set keeps `RunAsNode` on (read on the wire of every fused artifact), and
  on Windows the fused Host started under `ELECTRON_RUN_AS_NODE=1` from `app.asar`, with `OnlyLoadAppFromAsar` and
  embedded asar integrity validation both on and an integrity record that matches. On macOS and Linux the Host was
  never spawned, so no fuse stopped it there either: the failure is the versioned copy's manifest check, before any
  spawn.
- **Why the manifest did not match.** electron-builder 26.15.3 (`app-builder-lib/out/platformPackager.js`, `doPack`)
  runs the afterPack hook first and flips `electronFuses` after it ("the fuses MUST be flipped right before
  signing"). The product's afterPack writes `host-manifest.json` (scripts/build/afterPack.mjs), so the manifest hashes
  the binary before its fuses change: the executable on Linux, `Electron Framework` on macOS. On Windows the product's
  afterSign hook writes the manifest again after electron-builder's signing step, which is why Windows matched; macOS
  and Linux have no such rewrite. Today's release build is not affected: it flips no fuse.
- **Fixed in the lane, measured in run 3.** The spike configuration no longer uses `electronFuses`: its own afterPack
  hook (`spikes/S-019-2/afterPack.fused.mjs`) flips the same set through electron-builder's `addElectronFuses` (the
  documented afterPack alternative), then runs the product's afterPack, which writes the manifest last. The lane now
  runs `scripts/build/verify-packaged-host-manifest.mjs release-fused` right after packaging the fused build, as
  `ci.yml` does for `release/`, so a manifest that does not match fails at packaging and not only at the Host's start.

## Decision

- **The recorded fuse set per target, for ISSUE-269's `scripts/release/fuses.expected.json`:** all three OSes take the
  full ADR-019 item 5 set (`RunAsNode` on, cookie encryption on, `NODE_OPTIONS` and inspect arguments off,
  `OnlyLoadAppFromAsar` on, embedded asar integrity validation on). It is verified on the wire of every macOS, Linux and
  Windows artifact of the release targets.
- **No architecture conflict between ADR-019 item 5 and ADR-002 D1** was found: the Windows Host starts under the full
  set. No amendment is proposed.
- **For ISSUE-269: flip the fuses before the Host manifest is written.** With `electronFuses`, the packaged manifest
  lists the unfused binary on macOS and Linux and the Host never starts there. ISSUE-269 flips the fuses in the afterPack
  hook before `writePackagedManifest` (as the spike hook now does), or rewrites the manifest after the flip on every OS;
  `verify-packaged-host-manifest.mjs` already fails a build that gets this wrong.
- **Linux has no embedded asar integrity record.** ISSUE-269 lists asar integrity on Linux as a known limit of the
  shipped Linux targets (TC-269-02), whatever the fuse says.
- **Verdict passed (run 39205769685).** The exit criterion, "fuse set per target recorded and verified in packaged
  builds", is met: the set is recorded above and read on the wire of every release-target artifact of the three OSes in
  three runs. The fused Host starts on Windows, macOS and Linux, so the set does not break ADR-002 D1. Today's release
  build still carries the unfused set; flipping it is ISSUE-269's work, with `spikes/S-019-2/fuses.packaged.mjs` kept as
  its release check. The signed and notarized macOS build is not read here (the lane does not sign); ISSUE-269's release
  check reads it when the owner signs a release. Linux's missing asar integrity record is ISSUE-269's known limit, as
  above, and no run tested whether a tampered asar is refused.
