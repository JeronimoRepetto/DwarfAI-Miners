# S-032-1 — inferred turn ends and observed asks, per adapter

## Question

Spike register S-032-1 (ADR-032 items 4–5): for observed Claude (transcript only), OpenCode and Antigravity, which
rule infers a turn end, and what `INFERRED_TURN_END_MS` should it use? And per provider without an answer channel,
does an observed ask (a permission prompt, a question) leave evidence that sets `observedPermission` and
`observedQuestion` to `detected`?

## Setup

The evidence is a set of real-CLI recordings with the maintainer's own login (`17` §5.5). This issue built:

- `spikes/S-032-1/turnGaps.mjs`: over a transcript (Claude JSONL or a Codex rollout), per turn, the records, the
  duration and the **longest silence between two consecutive records while the turn was still working**, which is the
  floor any inference timeout must exceed. It also reports what the capture ends on: a tool call still waiting for its
  result (the candidate evidence of an ask), the provider's own turn end, or the last record's kind. Durations, kinds
  and tool names only.
- The cases, in `spikes/SP-06/observer-cases.md`: `tool-continuation` and `two-turns` for the silences, and
  `permission-ask` and `question-ask`, captured **while the CLI waits** for the person, for the evidence.
- `spikes/S-032-1/turnGaps.os.test.mjs` (OS lane, synthetic input, Claude and Codex shapes).

## Decision

- **Inferred ends (ADR-032 item 5): every adapter in scope keeps the documented default rule.** A turn end is
  inferred when there is "no new transcript record for `INFERRED_TURN_END_MS`, default 30 s, and the last record is
  an assistant message". The end is marked `inferred`: it moves the dwarf `working → idle`, and it never fires a cue,
  "Turn finished" wording or a departure. ISSUE-070 (the observation loop) and ISSUE-100 build that, with the 30 s
  default for observed Claude, OpenCode and Antigravity.
- **Observed asks: the initial `15` §2.5 values stay** until a recording re-measures them: Claude (transcript plus
  session registry) `detected` / `detected`; Codex (rollout) `none` / `detected`; OpenCode with its integration off
  `none` / `none`, and with "permission requests" `on-verified` `detected` / `none` (questions UNVERIFIED); Antigravity
  `none` / `none`. Each `none` is a documented limitation (OQ-35 A). ISSUE-070 reports asks only where its provider's
  row says `detected`.
- **Recorded per adapter** means: `turnGaps.mjs` over that adapter's `tool-continuation` and `two-turns` recordings
  gives the longest working silence, and the record states the timeout adopted (never below that silence, never below
  30 s). The `permission-ask` and `question-ask` captures state, per provider, whether the waiting ask left a
  record (a tool call still waiting, Claude's session registry `status: 'waiting'` with its `waitingFor` word), and `15`
  §2.5 is updated with version and date.
