# S-021-3 — Claude `Stop` / `SubagentStop` hook per turn end

## Question

Spike register S-021-3 (ADR-021 item 4): does Claude's `Stop` hook fire once per turn end, and how does
`SubagentStop` behave?

What it gates: `turnEnd` for "Claude observed with hook". In v1 it gates no issue: observed Claude keeps `turnEnd`
none (`15` row C5, ADR-021 item 4), and this record only informs a later change. Owner role: driver engineer. Issue:
ISSUE-325.

## Setup

Real-CLI lane (`17` §4, §5.5): the same stream-json process as S-022-1 path (a), with the same isolation
(`S-022-1.md`, Setup), plus `Stop` and `SubagentStop` command hooks given through `--settings`. The hook is a scratch
recorder that writes the payload's field names and a few values. Turns: T1 a plain reply, T2 one Read tool call, T3 one
`Agent` subagent (general-purpose) that ran Read. Then one interactive TUI turn (S-022-1 path (b), run 7).

## Commands

```text
claude -p --input-format stream-json --output-format stream-json --verbose --replay-user-messages
  --include-hook-events --setting-sources project --strict-mcp-config --permission-mode default
  --settings <hook settings json> --session-id <session-id>
```

## Results

Windows 11 Pro 10.0.26200, x64, Claude Code 2.1.301. macOS and Linux: **not run**.

- **`Stop`: exactly once per turn** (1/1/1), with `stop_hook_active: false`, 11 to 14 ms before each `result`. It did not
  fire per assistant message or per tool round trip (T2 and T3 had two model turns each).
- **`SubagentStop`: once** for the one subagent (T3), with `agent_type: general-purpose` and an `agent_id`, before that
  turn's `Stop`.
- Payload fields. `Stop`: `background_tasks, cwd, effort, hook_event_name, last_assistant_message, permission_mode,
prompt_id, session_crons, session_id, stop_hook_active, transcript_path`. `SubagentStop` adds `agent_id,
agent_transcript_path, agent_type`. The interactive mode adds `scratchpad_dir`.
- With `--include-hook-events`, stream-json also shows `system/hook_started` and `system/hook_response` for each.
- The transcript gets one `system/stop_hook_summary` record per `Stop` (3/3 stream-json, 1/1 interactive).
- Interactive TUI (one turn): `Stop` fired once.
- Not observed: compaction, interrupted turns, background tasks, and whether `stop_hook_summary` appears with no `Stop`
  hook configured.

## Decision

- **Passed for the cases run** (a plain reply, a tool use, one subagent, an interactive turn) on Claude Code 2.1.301,
  Windows: the `Stop` hook fires once per turn end, after any `SubagentStop`.
- **`turnEnd` stays `none` for observed Claude in v1** (ADR-021 item 4; `15` row C5). The record informs a later change
  that would let a DwarfAI `Stop` hook mark the turn end; compaction and interrupted turns must be measured before that.
- macOS and Linux: not run here.
