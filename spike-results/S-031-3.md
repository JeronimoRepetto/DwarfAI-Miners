# S-031-3 — `opencode attach` password delivery

## Question

Spike register S-031-3 (ADR-031 D1; ADR-009 D4, review N-05): can `opencode attach` connect without the password
passing through argv, environment or a DwarfAI-written file (ADR-017 item 3)?

What it gates: `console: 'attach'` for launched OpenCode (`log` until then), and the protection of a Host-launched
`opencode serve` (option (c), the `acp` fallback, until (a) or (b) is verified) (ISSUE-155). Owner role: driver engineer.
Issue: ISSUE-325.

## Setup

Real-CLI lane (`17` §4, §5.5), same machine, exception and isolation as `SP-12.md` (Setup). The server password was a
random value generated by the probe for this run only; it is not in any committed file.

## Commands

```text
opencode attach --help
opencode serve --help
OPENCODE_SERVER_PASSWORD=<random> opencode serve --port <port>
GET /session        # without auth, with a wrong password, with the right password
```

## Results

Windows 11 Pro 10.0.26200, x64, OpenCode 1.18.32. macOS and Linux: **not run**.

- `opencode attach` takes the password only as `-p, --password` (argv) or `OPENCODE_SERVER_PASSWORD` (env).
- `opencode serve` has no socket or pipe endpoint, only `--hostname` / `--port` (TCP).
- With the variable set: `/session` without auth → 401, wrong password → 401, right password → 200. Without it, serve
  prints `Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured.`

## Decision

- **Failed.** The only password deliveries are argv and env, both forbidden by ADR-017 item 3, and there is no
  owner-only endpoint. **Launched OpenCode keeps `console: 'log'`, and the `acp` fallback (option (c)) stays** for the
  protection of a Host-launched server (ISSUE-155).
- An open outcome becomes an R-16 known limit at v1. macOS and Linux: not run here.
