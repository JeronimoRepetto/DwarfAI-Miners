# SP-14 — ending an OpenCode session inside a shared server

## Question

Spike register SP-14 (ADR-014): which endpoint ends one OpenCode session inside the person's `opencode serve` without
signalling the shared server?

What it gates: how the OpenCode driver ends a session (ISSUE-155) and the `15` §6 C-28 fixture for OpenCode. Owner
role: provider dev. Issue: ISSUE-325.

## Setup

Real-CLI lane (`17` §4, §5.5), same machine, exception and isolation as `SP-12.md` (Setup), in the same `opencode serve`
run as the SP-12 OpenCode case. One turn was used, and it was aborted.

## Commands

```text
opencode serve --port <port>
GET  /doc                                         # the OpenAPI document
POST /session/{id}/prompt_async?directory=<cwd>   # 204
GET  /session/status                              # busy
POST /session/{id}/abort?directory=<cwd>          # 200 true
GET  /session/status                              # idle
GET  /global/health                               # 200
```

## Results

Windows 11 Pro 10.0.26200, x64, OpenCode 1.18.32. macOS and Linux: **not run**.

- The OpenAPI document lists `POST /session/{sessionID}/abort` ("Abort an active session and stop any ongoing AI
  processing or command execution"); `DELETE /session/{sessionID}` exists too.
- `prompt_async` (204) → status busy → `abort` → 200 `true` → status idle. The last assistant message carries
  `error: MessageAbortedError`, and the events show `session.error` then `session.idle`.
- The server stayed alive in the same process, and `/global/health` answered 200.

## Decision

- **Passed at OpenCode 1.18.32.** The abort endpoint ISSUE-155 uses is **`POST /session/{id}/abort?directory=<cwd>`**:
  it ends the turn of one session and leaves the shared server running. No signal is sent to the server process.
- `DELETE /session/{id}` was not measured, and is not claimed. macOS and Linux: not run here.
