# S-018-2 — window raise on a toast click (Windows 11)

## Question

Spike register S-018-2 (ADR-018 item 6): when the person clicks a DwarfAI notification on Windows 11, does
`revealDwarfChat` bring the mode window to the front, or do Windows' foreground rules leave it behind with a flashing
taskbar button (FM-049)? It becomes a release checklist item (`17` §4).

## Setup

- `spikes/S-018-2/clickRaise.cjs`: a throwaway Electron app. It opens the "mode window" behind another app
  (`behind`), minimized (`minimized`), or not at all (`none`), shows one toast after 10 s, and on the click restores,
  shows and focuses the window (creating it first in `none`), as `revealDwarfChat` will. It records Electron's focus
  state at the click and 0, 500 and 2 000 ms after it. A main-process error prints and exits; it cannot open a modal.
- `spikes/S-018-2/click-raise.md`: the manual procedure. Three runs; for each, the person answers whether the window
  came to the front, whether its taskbar button flashed, and whether its title bar was active.

## Commands

```sh
S0182_MODE=smoke S0182_REPORT=spike-results/S-018-2/windows-11-smoke.json <electron> spikes/S-018-2/clickRaise.cjs
```

Observed: exit 0. `Notification.isSupported()` is `true` with the AUMID set, and a hidden window was created and
reported. The smoke mode shows no toast and no visible window: this is the owner's working desktop, and the check
needs a person anyway.

## Results

| Run         | Came to the front | Taskbar flashed | Title bar active |
| ----------- | ----------------- | --------------- | ---------------- |
| `behind`    | not run here      | not run here    | not run here     |
| `minimized` | not run here      | not run here    | not run here     |
| `none`      | not run here      | not run here    | not run here     |

## Decision

- **Until this record says passed, ISSUE-114 follows FM-049:** on a click, `revealDwarfChat` still runs (it selects
  the mine, brings the card into view and opens the chat), and it asks the window to come to the front. Where Windows
  refuses, the taskbar flashes and the chat is open when the person switches to the window. ISSUE-114 relies on
  nothing this check has not shown; a foreground workaround would be a lead decision, not part of this default.
  ISSUE-123 lists the outcome in `parity-cut-1.md`.
- **Passed** means: in all three runs of `click-raise.md` the window came to the front with no taskbar flash, and each
  report's `after-reveal-500ms` entry says `focused: true`. Then the release checklist item reads "a toast click
  raises the mode window without a flash (S-018-2)", re-checked on each release build.
- **Failed** in any run: the record names the run, and FM-049 stays the behaviour there. Any mitigation is a new
  decision for the lead, not part of ISSUE-114.

Verdict **partial**. The harness runs on Windows 11 (smoke). No toast was clicked.
