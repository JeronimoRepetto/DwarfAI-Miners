# SP-10 — non-interactive deny and question-tool disabling

## Question

Spike register SP-10 (ADR-011): per provider version, with no prompt tool, does the provider deny a tool that needs
approval without hanging, and does its option really remove the question tool? Providers: Claude (`-p` with
`--disallowedTools AskUserQuestion`) and Antigravity (`agy` options).

What it gates: the permission modes of providers without an answer channel, the Claude part only when the stream-json
driver is offered, and the Antigravity launch. Owner role: provider devs. Issue: ISSUE-321 (Claude part); the
Antigravity part is ISSUE-325.

## Setup

Real-CLI lane (`17` §4, §5.5). **Run by an agent on the maintainer's Windows 11 machine on 2026-10-16, under a one-off
owner exception to AGENTS.md §0.3, with the owner's own Claude login and no human at the screen.** Same scratch tool,
throwaway repository and environment as `SP-08.md` (Setup), but with **no prompt tool and no MCP config**. The owner's
Claude settings were not changed.

## Commands

```powershell
node $K\sp3a.mjs run sp10-deny      # asks Claude to create sp10-deny-marker.txt with the Write tool
node $K\sp3a.mjs run sp10-question  # asks Claude to use AskUserQuestion
```

argv (from the summaries):

```text
claude -p --input-format stream-json --output-format stream-json --verbose --session-id <session-id>
  --permission-mode default --strict-mcp-config --disallowedTools AskUserQuestion
```

Then `node scripts/fixtures/scrub.mjs <case>.raw.*` per case (exit 0, after the thinking-block `signature` fix of this
change; the first scrub of both cases had stopped on that false positive) and the runbook's privacy check (no match).

## Results

Windows 11 Pro 10.0.26200.9457, x64, Claude Code 2.1.301. macOS and Linux: **not run**. Antigravity: **not run**.

| Case            | Pass value                                  | Observed                                                                                                              | Pass |
| --------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ---- |
| `sp10-deny`     | denials [Write], marker absent, normal exit | tools used [Write], `permission_denials` [Write], marker exists: false, result `success`, 2 turns, exit 0 at 17369 ms | yes  |
| `sp10-question` | AskUserQuestion not in tools, not used      | `askUserQuestionInTools: false`, tools used [], reply `unavailable`, exit 0 at 16292 ms                               | yes  |

- The denied Write came back to the model as the tool result "Claude requested permissions to write to
  `<REPO>\sp10-deny-marker.txt`, but you haven't granted it yet.", and the turn ended normally. Nothing hung.

### Antigravity part (ISSUE-325, 2026-10-17)

**Not run.** On the maintainer's Windows 11 machine the Antigravity CLI is not installed: `agy` is not on `PATH`, and
the launcher script left by its installer points at an `agy.exe` that does not exist. No deny or question-disabling run
was possible, and no Antigravity fixture is committed.

## Decision

- **Antigravity part: not run** (ISSUE-325). No deny policy is recorded for any Antigravity version, so the Antigravity
  driver stays development-only (ISSUE-156) and offers no launch that depends on a non-interactive deny. It needs a
  rerun with `agy` installed.
- **Claude part, Claude Code 2.1.301: passed.** With `--permission-mode default` and no prompt tool, `claude -p`
  denies a tool that needs approval, reports it in `permission_denials` and ends the turn. `--disallowedTools
AskUserQuestion` removes the question tool. A `policy-only` Claude launch can rely on both for this version.
- **Verdict partial**: the Antigravity part has not run (ISSUE-325 found `agy` not installed), and only Windows ran
  for Claude. macOS
  and Linux are not run and are not claimed.
