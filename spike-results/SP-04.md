# SP-04 — `node:sqlite`, `resourcesPath` and CLI resolution in a packaged Host

## Question

Spike register SP-04, as re-scoped by AMENDMENT-2 (OQ-52): in a packaged Electron 44 build, does a Host run under
`ELECTRON_RUN_AS_NODE` open the database with `node:sqlite`? Is `process.resourcesPath` usable there? Does the Host
resolve the person's own `claude` and other provider CLIs? The Agent SDK questions are withdrawn.

## Setup

`node spikes/SP-04/packagedHost.mjs` builds a throw-away app with the repository's electron-builder. It uses the `dir`
target for the current OS, nothing signed, `publish: never`, `asar: true`, and the Host script also unpacked. It then
runs the packaged executable with `ELECTRON_RUN_AS_NODE=1` on its own copy of the script, once from inside `app.asar`
and once from `app.asar.unpacked`, prints the scrubbed JSON, and deletes the build. The Electron 44.0.0 archive was
already in the local Electron cache, and the build took 4.3 s. The probe:

- opens a temp `dwarfai.db` with `node:sqlite` (`DatabaseSync`), sets `journal_mode = WAL`, turns foreign keys on,
  checks that an invalid foreign key is rejected, reads `sqlite_version()`;
- reports `process.resourcesPath` and whether it is the packaged app's resources directory;
- looks each provider CLI up on `PATH` with `PATHEXT` (`claude`, `codex`, `agy`, `opencode`, `kimi`, `kiro-cli`,
  `claude-agent-acp`). It only looks the CLIs up: it never runs one and never reads their configuration or
  credentials (ADR-008 item 2). Only the PATH position and the file extension are recorded, never a directory;
- on Windows, checks whether the packaged runtime starts a `.cmd` file with `shell: false`, directly and through
  `%ComSpec% /d /s /c`. It uses a synthetic `probe.cmd` in a temp directory, never a person's CLI.

## Commands

```sh
node spikes/SP-04/packagedHost.mjs --out spike-results/SP-04/windows-11-packaged-probe.json
```

## Results

Windows 11 Pro 10.0.26200 (`SP-04/windows-11-packaged-probe.json`). The results were identical for the script inside
`app.asar` and in `app.asar.unpacked`:

| Check                                 | Result                                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Runtime                               | Electron 44.0.0, Node 24.18.1, `ELECTRON_RUN_AS_NODE=1`, exit code 0                            |
| `node:sqlite`                         | opens; SQLite 3.53.1; `journal_mode` = `wal`; foreign key violation rejected; row read back     |
| `process.resourcesPath`               | a string, equal to `<exe dir>\resources`                                                        |
| `claude`                              | found; first match `.cmd`, a later PATH entry has `claude.exe`                                  |
| `codex`, `opencode`, `kimi`           | found; first match `.cmd` (`kimi` also has an `.exe` later on PATH)                             |
| `agy`, `kiro-cli`, `claude-agent-acp` | not installed on this machine                                                                   |
| `.cmd` with `shell: false`            | `spawn` fails with `EINVAL`; through `%ComSpec% /d /s /c <file>` (still `shell: false`) it runs |

## Findings

1. **`node:sqlite` works in the packaged Host under `ELECTRON_RUN_AS_NODE`** on Windows, with WAL and enforced
   foreign keys (ADR-005). No native module is needed. The packaged runtime wrote nothing to stderr (no
   `ExperimentalWarning`), while the repository's Node 24.11.1 prints "SQLite is an experimental feature" during
   `pnpm test`.
2. **`process.resourcesPath` is defined under `ELECTRON_RUN_AS_NODE`.** It points at the packaged app's `resources`
   directory, and a Host script runs both from inside `app.asar` and from `app.asar.unpacked`.
3. **PATH lookup finds the person's CLIs.** On Windows the first match is often a `.cmd` shim (the npm-style global
   install, or a wrapper the person put first on PATH). The packaged runtime (Node 24.18.1) refuses to spawn a `.cmd`
   with `shell: false` (`EINVAL`), while `%ComSpec% /d /s /c <file>` with `shell: false` runs it. Lint R17 forbids
   `shell: true`. How the Host starts a CLI whose first match is a `.cmd` belongs to the issue that owns provider
   process launch, and this record does not choose it. The fact is recorded so that issue does not assume an `.exe`.

## Decision

- **Database driver: `node:sqlite` is kept** (ADR-005). The `better-sqlite3` fallback is **not** adopted on the
  Windows evidence. ISSUE-033 builds on `node:sqlite`. If the macOS or Linux run below fails the `sqlite` check, the
  verdict becomes `failed` and ISSUE-033 follows the `better-sqlite3` fallback the register names. No other
  alternative applies.
- **Host runtime: `ELECTRON_RUN_AS_NODE` is kept** (ADR-002). `process.resourcesPath` can locate packaged resources,
  so ISSUE-021 may rely on it.
- **CLI resolution: PATH + PATHEXT lookup is kept.** The register's "explicit paths" fallback is not needed to
  _find_ the CLIs on Windows. Finding 3 is an input for the launch issue, not a change of this decision.
- Verdict **partial**: the exit criterion names three OSes, and only Windows ran here. macOS and Linux are owner steps.

## Owner steps still needed

On a macOS machine and on a Linux machine (each with the person's usual shell and at least `claude` installed), at the
repository root:

1. Run the probe:

   ```sh
   pnpm install --frozen-lockfile
   node spikes/SP-04/packagedHost.mjs --out spike-results/SP-04/<os>-packaged-probe.json
   ```

   Use `macos-<version>` or `linux-<distro>-<version>` for `<os>`. electron-builder downloads the Electron 44.0.0
   archive for that OS if it is not cached. Nothing is signed or published.

   Expected, for every entry under `runs` (`asar`, `unpacked`, and on macOS also `asar-guiDefaultPath` and
   `unpacked-guiDefaultPath`): `exitCode: 0`, `report.sqlite.ok: true` with `journalMode: "wal"` and
   `foreignKeyEnforced: true`, `report.resourcesPath.type: "string"` with `isExecDirResources: true` (macOS:
   `Contents/Resources`), and `report.clis.claude.found: true` in `asar` and `unpacked`.

2. On macOS, read the `*-guiDefaultPath` runs. They use the PATH a Finder-launched app gets (`sysctl user.cs_path`),
   which is what a UI started from the Dock passes down. If `claude.found` is `false` there, record it under
   "Findings": a Host started from a Dock-launched UI would need the login-shell PATH or explicit paths (the register's
   fallback), and the gated issue must decide which.
3. Check the JSON holds no user name or home path (the script replaces them with `j` and `~`). Add the OS to `os:` and
   its versions to `versions:` here. Set `verdict: passed` if every expected value above holds on both OSes, or
   `failed` with the fallback named under "Decision" if `node:sqlite` fails. Then commit:

   ```sh
   git add spike-results/SP-04.md spike-results/SP-04/
   git commit -m "docs(spikes): record SP-04 on macOS and Linux"
   ```
