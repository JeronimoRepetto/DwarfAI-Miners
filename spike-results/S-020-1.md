# S-020-1 — the readiness line of `claude -p` stream-json

## Question

Spike register S-020-1 (ADR-020): which line tells that `claude -p --output-format stream-json` is ready on the
installed version, and does it come before or only after the first message on stdin? How does an early failure look?

What it gates: the 3 s early-failure window of the Claude `stream-json` driver (ADR-020; today `earlyFailure:
'exit-only'`) and its C-01 and C-04 fixtures. Owner role: driver engineer. Issue: ISSUE-321.

## Setup

Real-CLI lane (`17` §4, §5.5). **Run by an agent on the maintainer's Windows 11 machine on 2026-10-16, under a one-off
owner exception to AGENTS.md §0.3, with the owner's own Claude login and no human at the screen.** Same scratch tool,
throwaway repository and environment as `SP-08.md` (Setup). The owner's three SessionStart hooks ran in every process
(two success, one error each time); their lines appear in the fixtures.

## Results

Windows 11 Pro 10.0.26200.9457, x64, Claude Code 2.1.301. macOS and Linux: **not run**. Times are from the spawn.

| Case               | First stdout                                                                | First stdin | `system/init`                                                            | Result                                               | Exit          |
| ------------------ | --------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------ | ---------------------------------------------------- | ------------- |
| `s0201-readiness`  | 386 ms: 3 × `system/hook_started`, 3 × `system/hook_response`               | 8043 ms     | 10174 ms, **after** the first input; session id equals the requested one | `success`, reply `hello`, 15329 ms                   | 0 at 19490 ms |
| `s0201-early-exit` | 431 ms: `result` `error_during_execution`, `is_error: true`, `num_turns: 0` | none        | **never**                                                                | stderr "No conversation found with session ID: <id>" | 1 at 3087 ms  |

- Before any input, Claude printed only the SessionStart hook lines. `system/init` came only after the first stdin
  message, so it cannot signal readiness before the first turn is sent.
- The early failure printed its error `result` line about 0.4 s after the spawn and no `system/init`. The process
  itself exited only at 3087 ms, about 2.6 s later and just past a 3 s window measured from the spawn.

## Decision

- **Readiness line for 2.1.301: `system/init`, emitted only after the first stdin message.** The driver must not wait
  for it before writing the first turn. `system/hook_started` and `system/hook_response` lines may come first and are
  not readiness.
- **Early failure: a `result` line with `is_error: true` before any `system/init`.** It came at 431 ms, while the exit
  came at 3087 ms. A rule that waits for the exit alone can miss a 3 s window, so the measured rule for ISSUE-150 is the
  error `result` (or an exit) before `system/init`. ISSUE-150 replaces `earlyFailure: 'exit-only'` from this record and
  owns the exact value.
- **Only Windows ran.** The exit criterion is per version and date, and it is met for 2.1.301. macOS and Linux are not
  run and are not claimed.
