# S-008-1 — license record per bundled adapter or library

## Question

Spike register S-008-1 (ADR-008 item 1; ADR-009 D5; `15-provider-driver.md` §2.4, §8): for each bundled adapter or
library, the license, redistribution permission and GPL-3.0-or-later compatibility, its NOTICE and attribution
obligations, and the version-pinning policy. The Claude Agent SDK and `claude-agent-acp` are out of scope: they are
never bundled (OQ-52, AMENDMENT-2).

What it gates: bundling each package as an app dependency (OQ-48 A, OQ-52). Until a package passes, an executable
adapter (`codex-acp`) is installed by the user, and an in-process library (Kimi SDK, ACP TS SDK) cannot be, so the
drivers that need it are not offered (`15` §2.4). Gates: the step 3a entry for the ACP TS SDK (with SP-08), the Kimi
and Kiro entry for the Kimi SDK, and v1, which needs every bundled package closed (`21` §8 R-06, §9). Owner role:
release/legal. Issues: ISSUE-321 (the ACP TS SDK entry), ISSUE-326 (the Kimi SDK entry), ISSUE-328 (closes the record
with one row per bundled package).

This record also holds the row for the keyring library of SP-16 (ADR-017 item 2). That library is bundled too, and
`20` §2.4 asks for a license line for every new production dependency.

## Setup

**The facts were gathered by an agent on the owner's behalf on 2026-10-16, and the decisions are the owner's**, as the
release/legal owner of S-008-1. The agent read registry metadata with `pnpm view`. It downloaded the three tarballs
from `registry.npmjs.org` into a scratch folder under `%TEMP%`, checked each tarball's SHA-512 against its
`dist.integrity`, unpacked them with Windows `tar.exe`, and read the files. Nothing was installed into the repository.

The pins are the newest release that was at least 14 days old on 2026-10-15. A pin that moves later gets a new row.

## Decision

- **`@agentclientprotocol/sdk` 1.6.0: bundled**, pinned exactly at 1.6.0, with its Apache-2.0 text in the third-party
  notices (owner, 2026-10-16). This is the S-008-1 half of the step 3a entry for the ACP TS SDK. It opens ISSUE-151's
  path (Claude through a user-installed `claude-agent-acp`), together with SP-08. `claude-agent-acp` itself stays
  user-installed and is never bundled.
- **`@napi-rs/keyring` 2.1.0 and `@napi-rs/keyring-win32-x64-msvc` 2.1.0: bundled**, pinned exactly, with the main
  package's MIT text in the notices for both packages (owner, 2026-10-16). This is the license line that the
  dependency-only PR adding the library needs (SP-16).
- **The other eleven `@napi-rs/keyring` platform binaries 2.1.0: bundled**, pinned exactly (owner, 2026-10-16).
- **`@moonshot-ai/kimi-agent-sdk` 0.1.8: bundled**, pinned exactly; the license inconsistency is recorded and upstream
  clarification is requested (owner, 2026-10-16). This is the S-008-1 half of the Kimi SDK entry (ISSUE-326). SP-07
  failed on 2026-10-17 (`SP-07.md`), so the Kimi driver is not built (ISSUE-158 closes as not needed) and the SDK is
  not added as a dependency in v1; the row stands for when Kimi joins the catalog.
- **`@zed-industries/codex-acp` 0.16.0: not bundled, user-installed** (owner, 2026-10-16).
- **Verdict passed.** Every package in scope has a decided row. A package or pin added later gets a new row. The
  ISSUE-272 report confirms the Kimi SDK dependency licenses when it is added.
