# SP-08 — Claude `--permission-prompt-tool` presence and routing

## Question

Spike register SP-08 (ADR-009 D4, D6 as amended by AMENDMENT-2): is `--permission-prompt-tool` present in the installed
`claude` version, and do permission requests and AskUserQuestion (AQ-30) route through it?

What it gates: the `stream-json` Claude driver's `launch`, `permission` and `question` capabilities, and so the step 3a
entry for a Claude driver (`21` §9; OQ-67). Owner role: provider devs. Issue: ISSUE-321.

## Setup

Real-CLI lane (`17` §4, §5.5). **Run by an agent on the maintainer's Windows 11 machine on 2026-10-16, under a one-off
owner exception to AGENTS.md §0.3, with the owner's own Claude login and no human at the screen.** The probe is the
scratch tool `sp3a.mjs` of the owner runbook (not committed). Each case starts the person's own `claude.exe` with no
shell, in a throwaway Git repository under `%TEMP%`, sends one fixed prompt on stdin and records every stream. The
prompt tool is a stub MCP server started by Claude from an `--mcp-config` file; it answers allow, deny, or allow with
the first option of a question. No auto-approve flag was used. Every inherited `CLAUDE*` environment variable of the
agent's own session was removed before each run; the owner's Claude settings were not changed, so their three
SessionStart hooks ran in every process.

## Commands

```powershell
# part 1: the --help probe (no quota)
node $K\sp3a.mjs help
# part 2: routing (one small turn each)
node $K\sp3a.mjs run sp08-allow
node $K\sp3a.mjs run sp08-deny
node $K\sp3a.mjs run sp08-question
```

argv of each part-2 process (from the summaries; `<session-id>` and `<mcp-config>` are placeholders):

```text
claude -p --input-format stream-json --output-format stream-json --verbose --session-id <session-id>
  --permission-mode default --permission-prompt-tool mcp__dwarfai__permission --mcp-config <mcp-config>
  --strict-mcp-config --disallowedTools AskUserQuestion
```

`sp08-question` runs without `--disallowedTools AskUserQuestion`.

**Two runs of part 2.** Run 1 used the unedited tool: it skips the three cases when `--help` does not list
`--permission-prompt-tool` as its own option, so no Claude process started (summaries in `SP-08/run-1-skipped/`). Run
2 used a scratch copy whose only change is that skip rule, which also accepts the flag when `--help` names it inside
the `--permission-prompts` description:

```diff
-    promptToolListed: OPTION('--permission-prompt-tool').test(text),
+    promptToolListed: OPTION('--permission-prompt-tool').test(text) || /--permission-prompts\s[\s\S]*?--permission-prompt-tool\)/.test(text),
```

Then the repository's scrubber over each case: `node scripts/fixtures/scrub.mjs <case>.raw.*` (exit 0 for every case,
after the thinking-block `signature` fix of this change), and the runbook's privacy check over every produced file
(no match).

## Results

Windows 11 Pro 10.0.26200.9457, x64, Claude Code 2.1.301. macOS and Linux: **not run**.

| Case            | Stub answer                 | Stub saw                                                                         | Calls                    | Outcome                                                            | Pass |
| --------------- | --------------------------- | -------------------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------ | ---- |
| `--help` probe  | —                           | —                                                                                | —                        | `--permission-prompt-tool` **not listed** as an option (see below) | —    |
| `sp08-allow`    | allow                       | `server/discover, initialize, notifications/initialized, tools/list, tools/call` | `Write->allow`           | marker exists: true; denials []; reply `done`; exit 0              | yes  |
| `sp08-deny`     | deny                        | same                                                                             | `Write->deny`            | marker exists: false; denials [Write]; exit 0                      | yes  |
| `sp08-question` | allow with the first option | same                                                                             | `AskUserQuestion->allow` | AskUserQuestion in tools: true; reply `Red`; exit 0                | yes  |

In every part-2 process the prompt-tool server reported `connected`, nothing was killed and stderr was empty.

- **The flag is hidden from `--help`, but accepted and working.** In 2.1.301, `claude --help` has no option line for
  `--permission-prompt-tool`. It lists a new option `--permission-prompts <target>`, whose description names the flag:
  `host` is "the SDK host or --permission-prompt-tool" (the default), `none` denies anything that would prompt. The CLI
  parsed `--permission-prompt-tool mcp__dwarfai__permission` without error in every process that passed it (also in
  S-020-1 and SP-15), and routed both permission requests and the question through it.
- **Question answer shape.** The stub answered the question with
  `{ behavior: 'allow', updatedInput: { ...input, answers: { "<question>": "<first option label>" } } }`, and Claude
  took it: the tool result reads `"Pick a colour"="Red"` and the reply is `Red`. Deny is `{ behavior: 'deny', message }`,
  and the message reaches the model as the tool result.
- **`--permission-prompts host` is untested.** No run passed `--permission-prompts`. With it and no
  `--permission-prompt-tool`, "host" would be the SDK control protocol on stdout, which the tool does not answer.
- `--permission-mode` choices listed by this version: `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`,
  `plan` (no `default`); `--permission-mode default` was still accepted and `system/init` reports
  `permissionMode: default`.

## Decision

- **For Claude Code 2.1.301, `--permission-prompt-tool` is present and routes**: permission requests reach it, Claude
  obeys allow and deny, and AskUserQuestion routes through it with the answer shape above. The stream-json driver
  (ISSUE-150) may set `launch`, `permission` and `question` from this record; the ADR-009 D6 fallback does not apply to
  this version.
- **The C-26 probe must not rely on `--help` listing the flag as its own option.** In this version it is absent from
  the option list, so a probe that reads only the option list would wrongly report the flag missing. ISSUE-150 decides
  the probe rule (for example, the mention inside the `--permission-prompts` description), and the help fixture
  `probe-help-without-prompt-tool` is its RED case.
- **`--permission-prompts host` is not covered by this record.** If the driver ever passes `--permission-prompts`, that
  combination needs its own run.
- **Only Windows ran.** The exit criterion is per version, and this version passed on Windows. macOS and Linux are not
  run and are not claimed.
