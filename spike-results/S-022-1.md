# S-022-1 — Claude echo match rule and normalization

## Question

Spike register S-022-1 (ADR-022 item 3, `transcript-match`): how does the Claude transcript echo a message delivered
(a) through `stream-json` stdin and (b) through the observed console relay, and which match rule and normalization fix
the ✓✓ mark?

What it gates: `reactionEvidence: 'transcript-match'` for Claude (ISSUE-166, ISSUE-170). Owner role: driver engineer.
Issue: ISSUE-325.

## Setup

Real-CLI lane (`17` §4, §5.5), same machine and exception as `SP-12.md` (Setup), with the owner's own Claude login
(`claude auth status`: `loggedIn: true`, `authMethod: claude.ai`). Isolation in every run: `--setting-sources project`
(none of the owner's user settings, hooks or plugins), `--strict-mcp-config` (no MCP servers), `--permission-mode
default`, and only the spike's own hooks through `--settings`. No auto-approve flag was used; the only tools that ran
were Read and Agent.

The probe text was the same on both paths: double spaces, a tab, a CRLF, an LF, trailing spaces, `é ✓ 🙂` and an em
dash (123 UTF-16 units).

- **(a) stream-json stdin**: `claude -p --input-format stream-json --output-format stream-json --verbose
--replay-user-messages --include-hook-events`, content as `[{type:'text', text}]`, three turns.
- **(b) observed console relay (Windows)**: the legacy relay itself, `buildConsoleInputWriteCommand(pid, text, true)`
  of `src/main/textDelivery/consoleInputWrite.ts`, run as `powershell -NoProfile -NonInteractive -Command` as
  `windowsTextDelivery.ts` does, from a scratch copy whose only change is explicit `.ts` import specifiers. The target
  was an interactive `claude` TUI in its own console (`cmd /c start "<title>" /MIN /D <cwd>`).

claude -p --input-format stream-json --output-format stream-json --verbose --replay-user-messages

claude --setting-sources project --strict-mcp-config --permission-mode default --settings <hook settings json>

## Results

Windows 11 Pro 10.0.26200, x64, Claude Code 2.1.301. macOS and Linux relay paths: **not run**.

- **(a) stream-json stdin.**
  - With `--replay-user-messages`, stdout re-emits each user message with a `uuid` before the first assistant event,
    and its text equals the sent text exactly (3/3).
  - The transcript has one `type:'user'` record per message, its content kept as an **array**, and its text
    **byte-equal to the sent text**: CRLF, tabs, runs of spaces and trailing spaces are kept, with no normalization
    (3/3).
  - The record `uuid` equals the replayed uuid (3/3), and its `timestamp` ≥ `sentAt` (+5 to +27 ms). The record says
    `promptSource: 'sdk'`, `turnOrigin: 'sdk'`, `entrypoint: 'sdk-cli'`.
- **(b) observed console relay.**
  - The transcript user record content is a **string** equal **exactly** to `normalizeConsoleText(sent)`: the relay
    collapses every whitespace run, tab and line break to one space and trims. Claude adds no normalization of its own.
  - Its `timestamp` ≥ `sentAt` (+302 ms). The record says `promptSource: 'typed'`, `turnOrigin: 'human'`,
    `entrypoint: 'cli'`, so a relayed message cannot be told apart from one the person typed.
- **"Followed by an agent record"** (both paths, 4/4): the next `assistant` record is not the user record's direct
  child. Its `parentUuid` chain passes through `attachment` records (1 hop on later turns, 12 on the first) and always
  reaches the user record.
- **Run history of path (b)** (`S-022-1/tui-run*`): run 1 (`stdio: 'ignore'`) left the TUI with no console and it
  exited; runs 2 to 5, under a fresh `%TEMP%` folder, ended at the folder-trust dialog (the keys sent to dismiss it
  declined it); in run 6 the message arrived while a setup screen was still up and was consumed by it; run 7 waited for
  `[REPL:mount] REPL mounted` and delivered. One screen-reading attempt (`ReadConsoleOutputCharacterW`) returned blank,
  then hung, and was abandoned.

## Decision

The match rule ISSUE-166 and ISSUE-170 follow for Claude `transcript-match` (ADR-022 item 3), fixed by the fixtures
below:

- **Delivered** ⇔ a transcript `type:'user'` record that is not a tool result and not `isMeta`, whose text (the string
  content, or the concatenated `text` parts of array content) **equals the text as the channel sent it**: the raw text
  for stream-json, `normalizeConsoleText(text)` for the console relay. No further folding, and its `timestamp` ≥
  `sentAt`.
- **Reacted** (✓✓) ⇔ an `assistant` record whose `parentUuid` chain, skipping `attachment` records, reaches that user
  record.
- stream-json may also correlate by uuid: the replayed `uuid` equals the transcript `uuid`.
- A relayed message is indistinguishable from a typed one in the transcript (`promptSource: 'typed'`); the match rule
  never depends on those fields.
- **Passed for both paths on Windows 11, Claude Code 2.1.301.** The macOS and Linux relay paths are not run here; until
  they are, they stay R-16 known limits at v1.
