# SP-05 — effective ACLs of the Host's pipe and run files

## Question

Spike register SP-05 (ADR-003 items 2, 3 and 12; ADR-013): what effective DACL does a Node-created named pipe get, and
are remote clients rejected? What ACL do the run files under `<hostDataDir>\run\` get (`ui.token`,
`viewers\<viewId>.token`, `mcp\<launchId>.cred`)? The run directory sits in the per-user `%APPDATA%` tree (`09` §1,
AMENDMENT-10).

## Setup

The harness `spikes/SP-05/pipeAcl.os.test.ts` (L8 Windows, `pnpm test:os`) reads each object's real security
descriptor. It then asks Windows' own access check (`AuthzAccessCheck` with `MAXIMUM_ALLOWED`) what each of these
principals would be granted:

- `owner`: the current user as a local interactive logon (must keep access, or the check proves nothing);
- `otherUser`: a user SID that is not the owner, with the groups every local logon has (Everyone, Local, Console
  Logon, Interactive, Authenticated Users, This Organization, Users);
- `anonymous`: Anonymous Logon, with Everyone and NETWORK;
- `remoteOwner`, `remoteOtherUser`: the owner and the other user as network logons (NETWORK instead of the local
  groups).

The principals are synthesized for the check (`AUTHZ_SKIP_TOKEN_GROUPS`). No account was created and no remote machine
was used. The protected pipe and run directory are created by a small helper, one C# program compiled at test time by
the .NET Framework compiler that ships with Windows (nothing installed). It uses `CreateNamedPipeW` with the SDDL and
`PIPE_REJECT_REMOTE_CLIENTS`, and `CreateDirectoryW` with the SDDL. The run files are written by Node itself
(`writeFileSync`, `flag: 'wx'`, `mode: 0o600`) inside a temp directory under `%APPDATA%`.

## Commands

```sh
SP05_REPORT=<tmp>/sp05.json pnpm vitest run --config vitest.os.config.ts spikes/SP-05
```

## Findings

1. **A Node-created pipe is readable by other users and by anonymous.** libuv creates the pipe with the default
   security descriptor, which grants read (`FR`) to Everyone (`WD`) and Anonymous (`AN`) and full access to
   Administrators. ADR-003 marked this as UNVERIFIED, and it is now measured. Node's `net` cannot set a pipe DACL.
   Whether libuv sets `PIPE_REJECT_REMOTE_CLIENTS` cannot be read back from a pipe, so a real remote client must
   show it (owner step 2).
2. **The ADR-003 item 2 DACL does what it says.** Created by the helper, the pipe grants nothing to another local user,
   to anonymous, or to a remote client of another user. The deny-NETWORK entry leaves a remote logon of the owner
   with `READ_CONTROL | WRITE_DAC` only, because Windows grants an object's owner those two rights before it reads the
   DACL. No data right is granted. `PIPE_REJECT_REMOTE_CLIENTS` also refuses such a connection before any access
   check (owner step 2 confirms it).
3. **An inherited ACL is not owner-only.** On Windows Node ignores `mode` for directories and files, so the run
   directory and its files take whatever the per-user tree passes down. On this machine the `AppData` tree carries an
   inherited read entry for another local account (`S-1-5-21-<machine>-1003`). It is not the owner's and not a
   built-in group, so that account can read every token Node writes there. The synthesized `otherUser` is refused
   there, which is why the harness also inspects the DACL entries: an arbitrary SID being refused does not prove that
   no _specific_ other account is granted access. ADR-003 item 3 requires the run directory to be owner-only ("its ACL
   inherited from the owner-only run directory"), and plain Node cannot make it so.
4. **Owner-only run files, measured.** When the helper creates `run\` with a protected DACL (owner and SYSTEM, inherited
   by files and folders), the files Node writes inside inherit only those two entries. Every other principal is
   granted nothing.
5. **Elevated administrators** can read any file or pipe regardless of its DACL (take-ownership and backup
   privileges). That holds for every design, and the frozen DACL does not add them.
6. **Tooling note.** `GetNamedSecurityInfo` and PowerShell `Get-Acl` fail with error 87 on a pipe created by libuv. The
   harness reads a pipe's descriptor through a client handle opened with `READ_CONTROL` only.

## Decision

- **The native DACL helper is adopted (ADR-003 item 2's own fallback).** SP-05 shows a pipe readable by other users,
  so the Host's endpoint pipe is created by a small native helper with the frozen DACL
  `D:P(D;;GA;;;NU)(A;;GA;;;<user SID>)(A;;GA;;;SY)` and `PIPE_REJECT_REMOTE_CLIENTS`. Until the helper exists, the
  token handshake stays the binding control and the Host sends no byte before authentication (item 2). ISSUE-022
  (endpoint ACL) builds this.
- **The same helper creates `<hostDataDir>\run\` with a protected owner-only DACL**
  (`D:P(A;OICI;FA;;;<user SID>)(A;OICI;FA;;;SY)`, the principals of the item 2 DACL). The token and credential files
  inherit it. This resolves a package detail consistently with ADR-003 item 3 (the run directory is owner-only and
  files inherit its ACL). No contract changes.
- The harness stays in the OS lane as the **ADR-003 security test**, with the helper stand-in. When ISSUE-022's helper
  exists, the test points at it.
- Verdict **partial**: the helper is adopted and the synthesized other-user and remote checks pass. Still missing are a
  real second Windows user, a real remote client, and the observed `PIPE_REJECT_REMOTE_CLIENTS` refusal. The owner
  steps below close it.

account; step 2 needs a second machine on the same network. Each starts the harness in hold mode, which keeps the
protected pipe and the three run files alive and prints their names.


   While it prints `SP-05 hold 300s: pipe \\.\pipe\dwarfai-sp05-…` and the three file paths, switch user (or

   ```powershell
   Get-Content -LiteralPath '<printed ui.token path>'
   ```

   Expected: both fail with access denied (`UnauthorizedAccessException`, or "Access to the path is denied"). The
   owner's harness run then ends with `3 passed`.

   machine's name:

   ```powershell

   ```

   Expected: the connection fails (access denied, or the pipe is not reachable). It never connects.
